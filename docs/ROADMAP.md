## 二、执行队列（按依赖排序）

### 序 1 · v0.7.0 数据基座与可信度

| 票 | 内容 |
|---|---|
| #16 | 价格历史快照管道（为走势图与智能成本指数攒序列） |
| #15 | 智能指数 Step 1-3：AA 取数脚本化 + 映射档位政策 + 分数漂移监控 |
| #10 | 数据漂移监控：档位结构 + 额度语义 |

**为什么排这里**：三条都是「时间敏感」或「别人依赖」的基座。

- #16 建完管道要满 6 周才画得出走势图，晚一个迭代就整体后移一个迭代；
- #14 的价格-能力散点，纵轴用的是 #15 提上去的分数覆盖（现 32/133），先做数据再画图，图不会做两遍；
- #15 与 #10 是同一套 drift 框架的两个消费面，同批做省一轮脚手架。

**本档 3 票**，超「每档 2 到 3 票」上限的余量解释：同文件面（三票全落在 `scripts/data/` 与 `src/data/generated/`），拆开等于在同一批文件上排两次队。

**收官判据**：`cli.mjs verify` 严重 0；`benchmarks-drift` 与 `plans-drift` 能各跑出差异清单；`pull-benchmarks` 断网失败不写文件；快照管道幂等（同日两次字节数不变）。

### 序 2 · v0.8.0 价格与用量曲线

| 票 | 内容 |
|---|---|
| #3 | 用量-成本曲线（横轴月用量，标排位反转点） |
| #14 | 价格新增曲线图（价格-能力散点 / 价格构成 / 走势） |

**为什么排这里**：直接依赖序 1 的两件交付。#14 的 Phase 3 数据源是 #16 的快照；Phase 1 的纵轴是 #15 的分数。且 #3 与 #14 共用一套手写 SVG 渲染层与同一份数据接入，同批做避免同批视图文件碰两遍。

**收官判据**：1440 / 375 无横向溢出；禁用 JS 时静态 HTML 里可见图与至少 5 个标注值；图上数值与表格同源（对拍 10 个点）；Pareto 前沿判定有单测。
