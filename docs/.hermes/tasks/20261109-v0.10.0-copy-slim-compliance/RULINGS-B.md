# 编排层裁定 B（v0.10.0）

## R1 首屏字数口径改为「只数可见文本」，阈值与页高目标按新基线重定

- **设计稿提出的冲突**：`/plans/` 768 首屏 918 字，与目标 350 冲突；设计判断「超标主因是 `<li>` 的 textContent 把折叠内文本算进去了」（`architecture.md` 一.5）。
- **编排层确认**：这是**我的探针缺陷**，不是页面缺陷。原实现用 `el.textContent`，闭合 `<details>` 里的整段说明也被计入；而闭合 `<details>` 的内容没有布局盒，用户根本看不到。
- **改法**：`scripts/metrics/copy-density.mjs` 的页面内度量改为 `TreeWalker` 遍历文本节点，跳过「闭合 `details` 内、且不在 `summary` 内」的节点与 `display:none` / `visibility:hidden` 的父节点。
- **修口径后的基线（v0.8.0 实测）**：

| 路由 | 375 | 768 | 1440 | 1440 页高 |
|---|---:|---:|---:|---:|
| `/` | 230 | 331 | 391 | 1881 |
| `/api-pricing/` | 101 | 186 | 134 | 14379 |
| `/plans/` | 119 | 247 | 148 | 4168 |
| `/calculator/` | 144 | 224 | 381 | 1928 |
| `/sources/` | 82 | 266 | 370 | 3802 |
| `/methodology/` | 237 | 544 | 520 | 2965 |

- **新判据**：数据页 375 ≤ 200 / 768 ≤ 350 / 1440 ≤ 220（沿用，实测只有首页超标：230 / 391）；说明页首屏不增；页高目标下调为**数据页 1440 降 ≥10%、说明页 ≥8%**（v0.8.0 起页高含 4 张图约 +3k px，仍按 15% 会逼着砍图表信息）。
- **知道但没有改的**：`/methodology/` 768 首屏 544 字仍是全站最高，属说明页设计使然，只要求「不增」。
