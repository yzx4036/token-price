# 本迭代 issue 全文（dossier）

## #19 套餐新档位发现：月费语境降噪 + 覆盖率提升 + 人工确认清单（承接 #17 P2）

## 一、背景
承接已关闭的 #17 的 **P2（套餐新档位发现）**。开票前编排层先跑了一遍现状，结论是：**「识别两类事件」这件事其实已经存在，但结果不可用**——所以本票不是从零造发现器，而是**降噪 + 提覆盖率 + 把结果变成可执行的候选清单**。

## 二、现状实测（2026-11-09，`node scripts/data/cli.mjs plans-structure-drift`）

```
覆盖率：可判 23/55 档 · 无法判定 32 档
疑似漏档 8 · 疑似合并 1 · 疑似下架 4 · 额度语义变化 7
```

- 两类事件**代码里已有**：`疑似漏档`（页面上有、仓库没录的价位）≈ 新档位候选；`疑似下架`（仓库录了、页面上找不到）≈ 消失价位。
- 但结果被**噪音淹没**，实测三类：
  1. **把 token 单价当套餐月费**：Anthropic `claude.com/pricing` 抓到 `0.01/0.05/0.08/…/500` 共 29 个「价格」，实际是每百万 token 单价；GitHub Copilot 抓到 `0.01`。
  2. **解析残渣**：OpenCode 页抓到 `1201001`（明显不是价格）。
  3. **页面本身抓不到**：32 档无法判定，含 Anthropic 四档（可用表多列无法定位）、火山方舟两档与智谱 GLM Coding Lite（纯前端渲染）。
- 现有判据只有「价格数字集合差集」，**没有「这个数字是不是月费」的校验**，所以报告一屏数字，人工没法判断。

## 三、本票要做的三件事

### B1 降噪：价格 token 必须是「月费」才有资格参与比对
- 只接收与「套餐月费」语境绑定的数字：相邻出现 `/月`、`每月`、`/mo`、`per month`、`Monthly` 等，或在套餐价格卡片区域内。
- 排除明显属于单价语境的数字：出现 `/百万`、`/1M`、`per 1M`、`/token`、`/千 token`、`USD/1M` 等相邻标记，或落在「模型价格表」结构内的。
- 排除异常值：非有限、负数、超过合理上限（如 > 100000 的月费视为解析残渣，需在报告里单列「疑似解析异常」而不是直接丢）。
- 判据：拿当前实测的两个反例做 fixture——Anthropic 页不得再报出 `0.01/0.125/.../500` 这批单价；OpenCode 页的 `1201001` 必须落到「疑似解析异常」而不是「新档位」。

### B2 覆盖率：为无法判定的厂商找可解析源
- 目标是让「可判档位」从 **23/55** 提升，优先覆盖现在明确无法判定的三家：**anthropic（4 档）/ volcengine（2 档）/ zhipu（2 档，GLM Coding Lite 等）**。
- 做法沿用 P1 已验证的路子：优先找官方 Markdown 版（页面地址加 `.md`）或 `llms.txt` 索引，实测 HTTP 状态与是否含「档名 + 月费」结构；抓不到就如实记「已验证不可用」，不许回退解析 JS 壳、不许抓第三方镜像。
- 判据：每家给「可用 / 需 JS / 不可用」结论与证据片段；覆盖率提升数要能被复现。

### B3 输出：把差集变成「人工确认清单」
- 每条候选给：厂商、页面 URL、候选价位、已录价位、**建议动作**（`新增档位` / `疑似下架需复核` / `疑似合并` / `疑似解析异常`）。
- 报告顺序：先「高置信候选」（B1 校验通过且语境明确），再「低置信/异常」。
- 仍然**只告警**：不写数据、不提交、不触发部署，退出码 0；基准/参数错误才非 0（与 v0.11.0 的 R15 一致）。

## 四、红线
1. 不改 `src/data/**` 的数据值；不新增运行时依赖；网络只在 CLI。
2. 不做模糊匹配猜档位（#15 已定），建议动作只是候选，落库永远人工。
3. 不碰图表几何、排序口径、页面上已有的展示逻辑。
4. 失败语义与 v0.11.0 一致：抓取失败 → `unavailable` + exit 0；基准/参数问题 → 非 0。

## 五、验收判据
1. **反例一（降噪）**：Anthropic 页面 fixture 喂进去，不得产出 `0.01 / 0.125 / 0.5 / 500` 这类 token 单价当作新档位；若页面确实无法定位套餐列，应记「无法判定：可用表多列」而不是「疑似漏档 29 条」。
2. **反例二（残渣）**：`1201001` 必须出现在「疑似解析异常」，不得进高置信候选。
3. **正例**：造一个「页面上真多出 ¥129 档」的 fixture，必须报为「新增档位」候选并给出建议动作。
4. **消失价位**：造一个「仓库有 ¥9.9、页面只剩 4.9/19.9」的 fixture，必须报「疑似下架需复核」，且不误报其它档。
5. 覆盖率：anthropic / volcengine / zhipu 三家各自给出可达性结论与证据；能提的档位数写进报告。
6. 只读验证：运行前后 `src/data` 哈希一致；`data-refresh.yml` 里的步骤仍是 report-only 且不阻塞。
7. 门禁全绿，且新增判据各配一个变异证明（改回旧行为必须变红）。
