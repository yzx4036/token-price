## #14 价格新增曲线图：价格-能力散点与价格构成（用量轴归 #3）

## 现状

全站只有表格，没有任何图形。三维数据（单价、能力分、币种）只能靠读者心算：

- 178 条条目里 32 条已有智能指数，但「便宜 100 倍的模型到底差多少」看不出来；
- 同一模型拆成输入 / 输出 / 缓存读 / 缓存写四个价，构成关系不可见；

技术现状：`package.json` 无图表库（无 chart.js / d3 / echarts），`src/` 里没有一处 SVG 图表。轻量站的优势不能靠引重型依赖换掉。

## 要做什么

### Phase 1 价格-能力散点（可立即做）

- 横轴：`blendPerMillion`（3:1 混合单价，复用 `src/lib/benchmark-view.ts`），对数刻度；
- 纵轴：智能指数；只画「有分且有价」的条目（当前 32 条 official，可扩展到聚合条目并显式区分标记）；

- 未评分条目不进图，图下方注明「N 条无评测数据未入图」，不拿 0 分顶替。

### Phase 2 价格构成（可立即做）

### Phase 3 价格走势（先攒数据）

- `data-refresh` 每次抓取后向 `src/data/history/price-history.jsonl` 追加一行快照（id + 四项价 + 币种 + 日期），只增不改；

## #3 增加用量-成本曲线（横轴月 Token 用量，标出排位反转点；当前只有静态表格）

## 问题

用户反馈：比价功能稍弱。当前只有「按单价排序的表格」，读者要自己心算才知道「按我的用量谁更便宜」。

## 建议方向

**核心洞察：单价低 ≠ 总价低。** 很多套餐有起步价、分级、峰谷，纯单价排序会误导。曲线图能直接回答「在我的用量下谁最省」。

具体做法：

1. **用量-成本曲线**：横轴月 Token 用量（对数刻度，1M → 1000M），纵轴月成本。
   每条线 = 一个模型/套餐，交点即「排位反转点」——这是表格给不了的信息。
   - 数据来源：API 条目已有 inputPrice/outputPrice/cachePrice；套餐有月费+额度，可折算成阶梯线
2. **在曲线图上标出「当前用量」竖线**，用 URL 参数 `?usage=50` 控制，默认 50M。
3. **诚实边界**：套餐的额度语义多为「5 小时 N 次请求」而非 token 数，无法精确折算成 token 成本。
   图上必须明确区分「可精确折算的 API 单价曲线」与「只能估的套餐」，不能混成一条线自欺。

## 技术选型

- 纯静态站，不引重型图表库。优先手写 SVG（约 200 行），或轻量 `chart.js`（需评估打包体积）。
- 必须预渲染：曲线数据点在构建期算好写进 HTML，不只靠客户端 JS。
- 深浅色主题都适配。

## 验收判据

- 1440px 与 375px 下曲线可读、不横向溢出
- 鼠标悬停/点击能显示某点的具体数值
- 禁用 JS 时至少有静态图或数据表可见（不得白屏）
- 曲线与表格数值必须一致（同一数据源，不各算一套）

## 备注

这一项改动最大，建议先做一版 spike 验证 SVG 方案再全量实现。
