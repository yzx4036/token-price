## ⚠️ 与验收标准第 1 条的实际差异（需要说明）

验收标准写的是「套餐表新增『等效 API 用量』**列**」。实际做成了**详情折叠区内的一行**，没有新增表格列。

原因：套餐表已有「折算可用 token」列，那是**官方额度换算**（智谱 Coding Plan Lite = 338M）。保本点是完全不同的另一个数（同一个套餐 = 23.6M），两者差 14 倍。再开一列就是两个 token 数并排且都叫「等效用量」，读者必然认为其中一个算错了。

改成：不新增列，在详情里把两个数**串成一条叙事**，并在方法论页写清楚区别：

- 「保本点」= 用量超过这个数，订阅才比按量便宜（23.6M）
- 「用满官方额度」= 官方给的额度按同样单价买要花多少（¥1,690 / 月费的 14.3 倍）

两个数数学上严格自洽：`338M ÷ 23.6M × ¥118 ≈ ¥1690`。读者先看到「用满能省 14 倍」知道划算，再看「低于 23.6M 该按量」知道临界点。

## 实现中发现并修掉的 5 个真实错误

**1. 跨厂商借价（算法对、语义错）**

最初允许「同地区同币种」兜底取最便宜，结果百度千帆 Token Plan 按智谱 `GLM-Z1-FlashX` 算出「¥9.9 ≈ 99M」、腾讯 CodeBuddy 按智谱算出「¥99 ≈ 990M」。读者会以为买腾讯套餐能享受智谱的低价。

改为**只在本厂商内选，选不到就返回 null**，页面标「不做等效折算」。

**2. 基准模型不在套餐可用模型内**

修完第 1 条后又发现：智谱 Coding Plan 只卖 `GLM-5.3 / 5.3-Flash`，但按单价中位数选中了 `GLM-4-Plus`。页面上出现「按 GLM-4-Plus 反推」而套餐根本用不了这个模型，读者一眼就能看出不对。

改为**优先匹配套餐自己的 `availableModels`**，匹配不到才退回全厂商中位数。

**3. 子串匹配让法律版冒充标准版**

`GLM-5.3-FlashX-Legal` 包含 `GLM-5.3-Flash`，一刀切子串会把法律版算进套餐。改为**两档匹配**：先要归一化后完全相同，一个都没有才放宽到子串。

**4. 320px 详情浮层超出视口 197px**

加这句话后，浮层里那一行被拉成 155px 高、整块 619px，桌面 1440×900 下底部超出视口 197px（1366×768 超出 264px）。加宽到 400px 让长句正常换行。

**5. 暗色主题下 ghost 按钮文字隐形（既有潜伏 bug）**

计算器页「展开全部」按钮在暗色主题下渲染成一个空框。根因是暗色块里 `.button { color: #08111f }` 是给「浅蓝底实心按钮」配的深字，而 `.button-ghost` 是透明底，继承深字后落在深色页面背景上等于隐形。实测 computed color `rgb(8,17,31)`。

这是项目里既有的潜伏缺陷，被本次新引入的 ghost 按钮暴露出来，已单独用一个 `fix:` 提交修复。

## 口径三条铁律（写进方法论页，也写进测试）

1. 只用本厂商、同币种、`official` 核验的单价，不跨厂商借价
2. 基准模型取该厂商**输出单价中位数**那档，不取最便宜的小模型（否则系统性高估套餐价值：Claude Pro 按 Haiku 算 100M，按 Sonnet 只有十几 M）
3. 输入输出按 **3:1** 混合计权，不按纯输出价算（纯输出忽略输入成本，会把保本点算高）
