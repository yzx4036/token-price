## B1 坏缓存绕过校验并被覆盖（静默失效）

- **问题**：`readJsonIfExists` 对「文件不存在」与「内容是 JSON `null`/`false`/`0`/`""`」都返回 null，`runPullBenchmarksCommand` 用 `if (previous)` 判空，于是坏内容被当成「首次无缓存」，跳过结构与降幅校验后**直接覆盖原文件并成功退出**。
- **落点**：`scripts/data/lib/benchmarks-pull.mjs` 的缓存读取与 `validateSnapshot` 调用处。
- **改成**：`existsSync(cacheFile)` 判存在、`readJson(cacheFile)` 取内容，**存在即无条件 `validateSnapshot`**，结构不合法抛 `CliError` 且零写入（两份原文件字节不变、非 0 退出）。只有「确实不存在」才跳过降幅基线。
- **反例测试**：已有缓存文件内容分别为 `null` / `false` / `0` / `""` / `{broken`，四种以上都要断言：非 0、`code` 为结构类错误、两份文件 SHA256 与 mtime 不变、且**没有发生写入**（用临时目录 + 读写计数或写入前快照比对）。

## B2 多个冲突 `initialModels` 只采信第一份

- **问题**：`parseRscModels` 用一次 `exec` 定位 marker 后直接 return 第一个数组。两份合法但内容冲突的载荷（例如 Opus 分数 59.11 与 60）会被静默取第一份。
- **落点**：`scripts/data/lib/benchmarks-pull.mjs` 的 marker 定位与数组截取函数。
- **改成**：找出**全部**候选数组；0 个 → `CliError`；多个且**规范化后内容相同**（例如 `JSON.stringify` 逐字节相等）→ 取任一；多个且内容不同 → 抛 `CliError`（歧义），非 0 且零写入。不允许「取第一份」或「取最后一份」这种猜测。
- **反例测试**：① 单个合法载荷解析成功；② 相同内容重复两次解析成功；③ 冲突内容两份 → 抛歧义错误且零写入；④ 第一处 `"initialModels":null`、第二处合法 → 明确行为（建议判歧义或按「只有 1 个合法候选」成功，二者择一并写进注释与测试）。

## B3 可用表多列互相掩盖（#10 核心）

- **问题**：可用性判定只看整行是否出现 `No` 且没有任何 `Yes/Unlimited/Expanded`。页面有多列（Plus / Pro / Free）时，Pro 的 `Yes` 会把 Plus、Free 的 `No` 一并抵消，报告出「无变化」。
- **落点**：`scripts/data/lib/plans-structure-drift.mjs` 的可用性解析段。
- **改成**：能识别表头与套餐列的，按**本套餐所在列**判可用性；无法可靠关联到列时，把该套餐的相关语义归入 `unknown` 并写明原因（`reason` 里说清「可用表多列无法定位本套餐列」），**不许给出干净的「无变化」结论**。
- **反例测试**：表头 `Model / Plus / Pro / Free`，行 `GPT-6 Luna / No / Yes / No`，三个套餐都登记可用该模型 → Plus 与 Free 必须报可用性变化，Pro 不报；再补一个无法定位列的输入，断言进入 `unknown` 而不是静默通过。

## B4 价格 SSR、额度 CSR 被报成额度变化

- **问题**：只要页面能抽出价格 `token` 就计入 `coverage.checked` 并进入额度比较；额度区是 JS 空壳时，缺证据被解释成「额度语义变化」。票面明确要求这种情形归「无法判定」。
- **落点**：`scripts/data/lib/plans-structure-drift.mjs` 的可判门槛与 `allowanceDifferences` 调用处。
- **改成**：**价格可判**与**语义可判**分开。语义侧要有最低证据门槛（例如页面里能抽到的额度类 token 数 ≥ 1，或命中记录里任一额度证据），不达标则把该套餐写入 `unknown`（reason 写明「价格可解析但额度语义未渲染」），不得报 `allowanceChanges`。
- **反例测试**：`<p>$20/month</p><div id="root"></div><script src="/pricing.js"></script>` + 记录里有 credits 与模型名 → 必须 `unknown` 且 `allowanceChanges` 为空；再补一个真实语义变化的页面（额度数字确实从 10000 变 20000）→ 必须报变化，防止把门槛设成「永远 unknown」。

## B5 workflow 顺序守卫对「命令缺失」恒绿

- **问题**：`tests/history.test.ts` 用 `indexOf(a) < indexOf(b)`，当 `a` 不存在时 `-1 < N` 仍为真，删掉 `verify` 步骤测试照样绿。
- **落点**：`tests/history.test.ts` 的 workflow 断言。
- **改成**：先断言三个位置**均 ≥ 0**（verify / snapshot / `id: diff`），再断言顺序；并补「删掉 verify 行」「把 snapshot 移到 diff 之后」两个内存反例（对字符串做 replace 后跑同一断言函数，断言此时必红）。
