## 已定决策（不要重问、不要另给方案对比）

D1 三批顺序固定：B1 快照管道(#16) → B2 智能指数取数脚本化(#15) → B3 漂移监控(#10)。前批验收绿才做后批。
D2 快照文件 = `src/data/history/price-history.jsonl`，一行一条事件：`{"date":"YYYY-MM-DD","kind":"delta"|"baseline","entries":{...}}`；`delta` 只含与上一份快照不同的条目；每月 1 日额外写一条 `baseline` 全量；单文件超过 2000 行再按月拆分（本轮只留阈值常量，不实现拆分）。同日重跑覆盖当日事件（幂等）。
D3 快照只收「合并后的 official 条目」（聚合条目不进历史）；比对字段 = `inputPrice/outputPrice/cacheReadPrice/cacheWritePrice/billingCurrency/provenance`，**`fetchedAt` 不参与比对**；变化类型 `price|currency|new|removed`。
D4 AA 取数 = 新命令 `pull-benchmarks`，实现文件 `scripts/data/pull-benchmarks.mjs`（照 `gen-benchmarks.mjs` 的形态：顶层 main() + `--check` 支持 + CliError）。产物两份：`.cache/aa-models.json`（全量快照，不入库）、`src/data/generated/benchmark-candidates.generated.json`（只含已按 slug 匹配上的条目，入库）。
D5 解析方式：取页面里所有 `self.__next_f.push([1,"…"])` 字符串字面量 → 各自 JSON 反转义 → 拼接 → 找 `"initialModels":` → 从其后第一个 `[` 做括号配平截取 → `JSON.parse`。禁止用正则直接抠自转义片段。
D6 失败语义：网络失败 / 解析失败 / 匹配结果与上次快照比模型数下降超过 30% ⇒ 退出码非 0 且**不写任何文件**（基线取 `.cache/aa-models.json` 的已有记录，首次无基线则不判降幅）。
D7 档位政策结构化：`src/data/estimates/benchmark-basis.json` 的 `methodology` 增加 `tierPolicy: { "mode": "highest-score" }`（保留现有中文说明字段，不删）。脚本按该政策从 AA 同名多档里取分数最高档，并把 `tierUsed` 写进产物。
D8 映射规则：`benchmark-basis.json` 的 `mapping{展示模型名 → aaSlug}` 仍是唯一权威映射表；新脚本只做「校验 mapping 里每个 slug 在今日快照中存在」以及「把 AA 中已匹配但 basis 未收录的候选列入 candidates 产物」，**绝不自动新增 mapping、绝不模糊匹配**。
D9 漂移命令：新增 `benchmarks-drift`（与既有 `drift` / `plans-drift` 并列），输出三类：分数变化（阈值 0.5 分）、档位切换（tierUsed 变）、slug 消失。只报告不改数据、不改文件。
D10 #10 的实现：新增 `plans-structure-drift` 命令，在既有 `scripts/data/lib/plans-drift.mjs` 旁边新增 lib（不要改坏现有 `plans-drift` 的行为与它的测试），判「档位结构（漏档 / 合并 / 下架）+ 额度语义变化」。
D11 不新增任何运行时依赖；`dependencies` 保持 vue / vue-router / zod。
D12 只改代码与测试，**不做任何 git 操作**（不 add / 不 commit / 不 checkout）。
