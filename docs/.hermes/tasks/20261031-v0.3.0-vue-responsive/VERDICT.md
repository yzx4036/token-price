## §2 阻断项裁定

### B1 · 375×667 首屏看不到价格 —— **接受，已修，已实测复验**

- **审查员依据**（静态计算）：filter 顶 ≈366.6px、首卡顶 ≈759.5px，超 667 首屏 92.5px。
- **我的独立实测（修前，CDP 375×667）**：`filterBar top=344 h=305`、`first-card top=738`、`first-price top=836` ⇒ **确认成立**，且比我原先只测的「filter top < 600」判据更该被抓住：我把 R8 的判据写宽了，只约束了筛选条位置、没约束**第一条价格**的位置。
- **返工边界**（只允许动这三处，不许扩战线）：
  1. `src/styles/global.css` `<768px` 段：`.filter-bar` 三下拉并一行（搜索独占一行），`.filter-summary` clamp 2 行，`.hero .meta` 压字号；
  2. 新增 `@media (max-width: 360px)` 段：再收纵向间距、clamp 1 行；
  3. `src/components/FilterBar.vue`：排序选项文案缩短（`输入价格（原币种）` → `输入价`），否则 109px 宽的 select 会截断成「输入价格（」。
- **复验读数**（修后，每档独立刷新 + 禁缓存）：

  | 视口 | 首个价格元素 top | 视口高 | 结论 |
  |---|---|---|---|
  | 320×640 | 623 | 640 | 通过 |
  | 375×667 | 620 | 667 | 通过 |
  | 414×896 | 605 | 896 | 通过 |

- **判据收紧（写进验收）**：R8 从「filter 顶部 < 600px」改为「**首个 `$`/`¥` 价格元素顶部 < 视口高**」，三档小屏都必须过。

### B2 · `scripts/deploy-site.sh` 被改，违反 N4 —— **接受违规事实，但责任方是编排层不是执行体，判「授权并单列验收」**

- **事实核查**：审查员写「执行体交付清单没有申报这项改动」——这句是**推断错误**。查明改动者是我（编排层），在派单**之前**做的，动机两条：
  1. 把新写的产物门禁挂进发布链（`verify-static-build.mjs`），让发布前必须过预渲染检查；
  2. 修 `node` 在无 tty 下是 winpty 别名、会拒跑并打印 `stdin is not a tty` 的假红（改用 `node.exe` 真身）。
- **裁定**：**授权该改动，但按「编排层改动」单列验收，不计入执行体违规**。理由：N4 的目的是防止执行体顺手改部署链；编排层自己维护门禁与发布链职责所在。**但流程上我确实违了自己的规矩**——单方面改动了已下发的「禁改清单」中的文件而未在任务书更新，这条记入 §5 遗留 T2（下次派单前，编排层自改的文件要么先改任务书再派单，要么单列授权段）。
- **该改动的验收（必须单独过，不能混在 Vue 改动里蒙过）**：

  | 检查 | 读数 |
  |---|---|
  | `bash -n scripts/deploy-site.sh` | OK |
  | 走 `deploy-site.sh` 完整链路 | `门禁 → 产物门禁 结论：通过 → 主页同步 1 文件 → 子站发布 10 文件 → 提交`（`SKIP_PUSH=1` 与真实发布各跑一次，均 RC=0） |
  | `node.exe` 真身替换是否消除了假红 | 是。改前 `verify-static-build.mjs` 在脚本内 `RC=1` 只打 `stdin is not a tty`；改后 RC=0 且输出正常报告 |
  | 残留裸 `node` 调用 | `grep '$(node \| node scripts' scripts/deploy-site.sh` = 0 |
