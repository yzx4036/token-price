# 任务书 · v0.4.0 比价体验重构（#4 → #2 → #1）

> 仓库：`<repo>` · 分支 `release/v0.1.0`
> 技术栈：Vite 8 + Vue 3.5 + TypeScript + Vue Router，**构建期预渲染六路由**
> 对应 issue：https://github.com/yzx4036/token-price/issues/4 · /2 · /1

## §0 一句话目标

在不改动数据层、不退化预渲染的前提下，让比价页「打开就能看到价格、能按自己的口径排序、能按国内外筛选」。

## §1 铁律（违反即返工）

1. **禁改 `src/data/**`**（含 entries / generated / providers）。数据零 diff 是硬不变式。
2. **禁改部署链**：`scripts/deploy-site.sh`、`scripts/site-publish.mjs`、`scripts/verify-static-build.mjs`、`site.config.json`。
3. **禁任何 git 操作**（不 commit / 不 push / 不 branch）。提交由编排层统一执行。
4. **不得为通过而放宽判据**：不删测试断言、不 `.skip`、不把失败项移出范围。
5. **预渲染不得退化**：六路由各自产出带真实价格的静态 HTML，禁用 JS 仍能看到价格。产物门禁 P1–P5 必须继续通过。
6. **跨币种不排名**这条口径必须保留：USD 组在前、CNY 组在后，组内按原币种比较。不得合并出跨币种的「最便宜」。
7. 不引入 UI 组件库、不引入图表库（本轮无图表需求）。

## §3 需求 #4：国内 / 国外厂商筛选

### 3.1 数据层不动
`providers.json` 每条已有 `region: "cn" | "intl"`（见 `src/lib/schema.ts` 的 `providerRegionSchema`）。直接用，不要改数据。

### 3.2 状态
`src/lib/filters.ts` 的 `FilterState` 增加：
```ts
region: 'all' | 'cn' | 'intl';
```
`DEFAULT_FILTERS.region = 'all'`。

### 3.3 筛选逻辑
`src/lib/pricing.ts` 的 `filterAndSortApiPrices` 增加 `region` 过滤。注意：
- `ApiPrice` 上没有 `region` 字段，需要按 `providerId` 查 providers 表
- **不要**把 providers 表塞进 `pricing.ts`（那是纯函数模块），改为让调用方传入 `regionByProviderId: Record<string, 'cn'|'intl'>`，或新增一个可选参数。保持函数可测试、无全局依赖。

### 3.4 UI
`src/components/FilterBar.vue` 增加国内/国外筛选，**用三段式分段控件**（全部 / 国内 / 国外），不用下拉框——少一次点击。要求：
- 触控目标高度 ≥44px
- 有 `aria-pressed` 或等效的可访问性语义
- 移动端（≤767）不与搜索框抢行，按现有 `filter-bar` 的 grid 排布适配
- 与搜索、厂商、溯源、排序四个条件**可叠加**

### 3.5 套餐页也要有
`src/views/PlansView.vue` 同样支持国内/国外筛选。套餐数据的 `providerId` 同样查 providers 表取 region。

## §4 需求 #2：点击表头排序

### 4.1 交互
- 表头 `<th>` 可点击，点击后按该列排序
- 再次点击同一列**反转方向**
- 头上要有方向指示（▲▼ 或等效），且**当前排序列**要有视觉区分
- 可排序列：输入价、输出价、Cache 读、Cache 写、上下文长度、厂商名
- 「溯源」「详情」列不可排序（不做点击态）

### 4.2 移动端卡片视图也要能排序
`<1024` 走卡片列表（`PriceCardList.vue`），没有表头。要求至少在筛选区提供排序入口（可复用现有排序下拉，但要支持方向切换）。

### 4.3 保留「跨币种不排名」
排序时**先按币种分组**（USD 组 → CNY 组），组内再按选中列排。这条是产品口径，不是技术细节——写错了整张表会误导读者。

### 4.4 URL query 同步（谨慎实现）
- 把 `region` / `sort` / `order` 反映到 URL query，例如 `?region=cn&sort=outputPrice&order=desc`
- **预渲染约束**：构建期 SSR 没有真实 URL query。必须做到：
  - SSR 阶段一律用 `DEFAULT_FILTERS` 输出
  - **只在 `onMounted` 后**读取 `window.location.search` 并应用
  - 不得在 setup 顶层直接读 `location`（会 hydration mismatch 报错或闪烁）
- 用户改变筛选/排序时用 `history.replaceState` 更新 URL（不要 `pushState`，避免后退栈被刷爆）

## §5 需求 #1：信息密度重构

### 5.1 编排层已定的设计裁决（照做，不要再选方案）

采用「**压缩头部 + 主次分层 + 顶部结论卡**」三者组合：

**A. 压缩头部（最优先，收益最大）**
1. 桌面端 `.hero` 里的 `details`（币种口径与免责说明）**默认折叠**。当前 `useFoldOpenByDefault()` 在桌面返回 true，改为桌面也 false（移动端可保持展开，因为窄屏更需要说明）。
2. 精简 hero：`h1` 下那句 meta 保留但压缩；免责说明收进 details，不要占首屏。
3. **目标：第一个价格出现位置从 826px 降到 ≤400px。**

**B. 表格主次分层**
1. API 页表格：主列只留「厂商/模型」「溯源」「输入价」「输出价」「详情」。
   - `Cache read` / `Cache write` 两列**收进详情 details**（它们本来就大多是「待核验」，占列不提供信息）
   - 表格从 7 列降到 5 列，列宽重新分配（百分比合计 100%）
2. 套餐页表格：主列只留「厂商/套餐」「月费」「额度核心」「详情」。
   - 「周期」「可用模型」「用途限制」**收进行内 details**
   - 「额度核心」显示额度语义的**首句或数字部分**（例如「5小时 6,000 次」），完整文本进 details
   - 目标：单行最高从 140px 降到 ≤60px

**C. 顶部结论卡**
每页 hero 下方加 2–4 张紧凑结论卡（复用一个新组件），内容全部**从真实数据算**，不得写死：
- API 页：国内最低输入价（厂商+价格）、国际最低输入价（厂商+价格）、条目总数
- 套餐页：人民币最低月费（厂商+档位+价格）、美元最低月费（厂商+档位+价格）、收录档位数
- 卡片高度 ≤80px，一行放得下 3–4 张（1440），移动端竖排

### 5.2 必须守住
- 「额度语义」等长文本**不得删除**，只能折叠——一次点击可见
- 禁用 JS 时，**被折叠的内容仍在 HTML 里**（`<details>` 天然满足），且**主列价格必须在 HTML 里可见**
- 移动端卡片视图（`PriceCard.vue`）也要做同样的主次分层，不要只改桌面
